# 声纹交互显式化：校验与入库均为用户显式动作，校验只产出建议

spec #9（issue #9）原案为"命名即入库 + 自动认人/纠错 + 库变动自动重认"。实践中发现两个根因问题：自动入库会把错归属的声纹沉淀进库、污染后续所有视频；库变动触发的自动重认会静默冲掉人工校正（ADR-0002）。我们决定：声纹交互全部显式化——说话人命名变为纯本地操作，"存入声纹库"为逐说话人按钮（按当前生效时段含人工校正抽声纹，同名追加向量）；"用声纹库校验"为按需动作，在当前生效时段之上运行，且**只产出建议**（沿用名字/合并同人簇/改派标错段），不直接修改任何数据；建议逐条经用户接受后并入人工校正层。spec #9 的 issue 保持原样（保留当时决策），本 ADR 记录修订。

## Considered Options

- **A. 保持全自动（spec #9 原案）**：被否决——静默丢失人工校正；声纹库被错归属声纹污染。
- **B. 自动认人保留、人工校正层置顶**：被否决——自动重跑时机对用户仍是惊讶（"我只是命了个名"）；自动层与裁决层叠加的优先级规则难以向用户解释。
- **C. 全显式 + 建议模式（选定）**：自动化只提建议、用户最终裁决，与人工校正层哲学一致；声纹库成为人工精选库，精度更高。

## Consequences

- 修订 spec #9 用户故事 1/2/8/10（自动入库、自动认人、改库自动重认、修正同步入库）；issue #9 不修改，作为当时决策的历史记录。
- 认人/纠错从自动分析链移除（分析为 ①②③④）；校验作为按需动作仍需进度与取消能力。
- 每集想复用声纹需多点一次校验并确认建议——可控的显性成本，换取零静默行为。
- 校验沿用既有算法与阈值（0.80/0.85/0.10），仅输出从"直接应用"改为"建议列表"。
